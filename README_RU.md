# Уменьшитель-инатор (Shrinkinator)

BepInEx-мод для **R.E.P.O.**, добавляющий в магазин новый предмет — пушку
«Уменьшитель-инатор». Выстрел распыляет зелёный туман: всё, что задел туман,
уменьшается в несколько раз.

- **Ценности (valuables)** уменьшаются **навсегда**: размер, масса и (опционально)
  стоимость масштабируются пропорционально кубу коэффициента. Повторные выстрелы
  стакаются, но не ниже `ValuableMinScale` (по умолчанию 20% от исходного размера).
  Уменьшенную ценность проще донести до точки эвакуации.
- **Враги и игроки** уменьшаются **на время** (по умолчанию 20 секунд), затем
  возвращаются к нормальному размеру. У уменьшенного игрока опускается камера,
  сужаются хитбоксы (можно проходить под тем, где раньше нужно было приседать)
  и укорачивается захват.
- Уменьшенные враги становятся **легче** (их проще поднимать физ-захватом),
  но **НЕ оглушаются** — стан специально не применяется.
- У пушки **6 зарядов** — реализовано через ванильную батарею (индикатор
  батареи = индикатор зарядов). Заряжается обычными зарядными станциями.

## ВАЖНО: мод нужен ВСЕМ игрокам

Мод работает через сетевую синхронизацию (Photon RPC): эффект применяет хост,
а визуал/физику воспроизводят все клиенты. **Мод должен быть установлен у всех
игроков в лобби** (и у хоста, и у клиентов), иначе возможны рассинхроны и
ошибки RPC.

## Установка

1. Установите **BepInEx 5.4.21** (x64) в папку игры и запустите игру один раз.
2. Установите **REPOLib** (Zehs.REPOLib 3.0.3+, разработка велась на 4.2.0) —
   положите `REPOLib.dll` в `BepInEx/plugins/`.
3. Положите `Shrinkinator.dll` в `BepInEx/plugins/Shrinkinator/`
   (папку создайте сами; можно и просто в `BepInEx/plugins/`).
4. Повторите для **каждого** игрока в лобби.
5. Пушка появится в магазине (раздел оружия), цена — в 1.5 раза дороже
   ванильного пистолета (настраивается).

## Сборка из исходников

Требуется .NET SDK 8.0+ (собирается под netstandard2.1). NuGet-пакеты
(`R.E.P.O.GameLibs.Steam`, `BepInEx.Core`, `UnityEngine.Modules`, `Zehs.REPOLib`)
подтягиваются из фидов, перечисленных в `NuGet.Config` (nuget.org, bepinex.dev,
samboy.dev, thunderstore):

```bash
cd Shrinkinator
dotnet build -c Release
# готовая DLL: Shrinkinator/bin/Release/netstandard2.1/Shrinkinator.dll
```

Если фиды samboy.dev / thunderstore недоступны — все нужные пакеты есть и на
nuget.org, лишние источники можно удалить из `NuGet.Config`.

## Конфигурация

Файл `BepInEx/config/com.kimi.shrinkinator.cfg` (создаётся после первого запуска):

| Параметр | По умолчанию | Описание |
|---|---|---|
| `ScaleFactor` | `0.35` | Множитель размера (0.35 ≈ в 3 раза меньше). Масса/цена — куб множителя. |
| `DurationSeconds` | `20` | Длительность уменьшения врагов и игроков (ценности — навсегда). |
| `CloudRadius` | `2.5` | Радиус облака тумана, м. |
| `MistRange` | `12` | Дальность распыления, если луч ни во что не попал, м. |
| `Charges` | `6` | Выстрелов от полной батареи. |
| `ValueScalePrice` | `false` | Уменьшать ли стоимость ценности вместе с размером. |
| `ValuableMinScale` | `0.2` | Минимальный размер ценности относительно исходного. |
| `ItemName` | `Уменьшитель-инатор` | Название предмета в магазине. |
| `PriceMultiplier` | `1.5` | Множитель цены относительно ванильного пистолета. |
| `ShootCooldown` | `0.8` | Пауза между выстрелами, с. |
| `UseCustomModel` | `true` | Кастомный визуал пушки (см. ниже). `false` — ванильный пистолет. Требует перезапуска. |
| `AimVerticalOffset` (Хват) | `0` | Угол ствола относительно взгляда, градусы. Ванильный пистолет: `-10` (бьёт ниже прицела); `0` — ровно по камере. |
| `GrabVerticalOffset` (Хват) | `-0.15` | Вертикальное смещение пушки в руке относительно линии взгляда, м (ваниль: `-0.2`). |
| `CenterOfMassInGrip` (Хват) | `true` | Центр масс в рукояти — убирает «маятниковое» болтание при удержании. |
| `AimAssist` (Хват) | `true` | Выравнивание оси дула по оси, которую физика держит по камере. |
| `GrabStrengthMultiplier` (Хват) | `1` | Множитель силы пружины удержания (1 = ваниль). |
| `TorqueMultiplier` (Хват) | `1` | Множитель скорости доворота за взглядом (1 = ваниль). |

## Хват и прицеливание

Пушка настроена так, чтобы **стрелять ровно туда, куда смотрит камера**, браться
в руки **за рукоять** и **не болтаться** при удержании. Настройки применяются
только к «Уменьшитель-инатору» — ванильные пушки не затрагиваются.

Как это устроено (по механикам ванильной игры):

- **Ствол = камера.** `ItemGun.UpdateMaster` каждый кадр удержания доворачивает
  пушку к осям камеры держащего через `PhysGrabObject.TurnXYZ(Euler(aimVerticalOffset,0,0))`.
  У ванильного пистолета `aimVerticalOffset = -10°`, поэтому он бьёт ниже прицела —
  у нас `0` (конфиг `AimVerticalOffset`). Дополнительно `AimAssist` выравнивает
  `gunMuzzle.forward` (отсюда идёт raycast выстрела) строго по `transform.forward`
  корня — именно эту ось держит физика удержания.
- **Хват за рукоять.** На префабе задана ванильная точка **"Force Grab Point"**
  (её читает `PhysGrabber`): при захвате за любую часть корпуса луч прикрепляется
  к рукояти. Точка перенесена в рукоять кастомной модели.
- **Нет болтания.** Центр масс (`rb.centerOfMass`, ванильная точка
  **"Center of Mass"**, которую читает `PhysGrabObject.Awake`) перенесён в ту же
  рукоять: сила захвата прикладывается к точке хвата, и когда она совпадает с
  центром масс, паразитного крутящего момента («маятника») не возникает.
- **Позиция в руке.** `GrabVerticalOffset = -0.15` держит пушку чуть ниже линии
  взгляда, чтобы не загораживать обзор (ваниль: `-0.2`).
- Силы удержания (`GrabStrengthMultiplier` / `TorqueMultiplier`) по умолчанию
  ванильные (`1`): после переноса центра масс в точку хвата усиливать их не
  требуется, но множители вынесены в конфиг для тонкой подстройки.

Перенос точек хвата/центра масс работает только с кастомной моделью
(`UseCustomModel = true`) — позиция рукояти берётся из неё
(`ShrinkinatorModelBuilder.GripOffsetBase`). При ванильном визуале остаются
штатные точки префаба пистолета, а прицельные поля (`AimVerticalOffset` и др.)
настраиваются в любом случае.

## Кастомная модель

Вместо визуала ванильного пистолета предмет использует **процедурную модель
«shrink ray gun»**: ретро sci-fi рей-ган (тёмный металлический корпус, бак со
светящейся зелёной «жидкостью», конусный ствол с зелёными кольцами, светящийся
наконечник, рукоять и боковые плавники — стилизация под «-инатор» Доктора
Дуфеншмирца).

- Модель **собирается полностью в коде** из Unity-примитивов
  (`GameObject.CreatePrimitive` — кубы, цилиндры, сферы, капсулы) — без Unity
  Editor и без каких-либо внешних ассетов (`src/ShrinkinatorModelBuilder.cs`).
- Сборка происходит **один раз на префабе-клоне до его регистрации** в REPOLib,
  поэтому в мультиплеере модель воспроизводится у всех клиентов автоматически
  (это обычные дети сетевого префаба), дополнительной синхронизации нет.
- Ванильные MeshRenderer'ы предмета отключаются (`renderer.enabled = false`,
  объекты не деактивируются — логика, звуки, muzzle flash и коллизии не тронуты).
  Коллайдеры примитивов удаляются — физика остаётся от ванильного префаба.
- `gunMuzzle` переносится на кончик нового ствола — луч/туман вылетают из нового
  дула. Масштаб модели подбирается по bounds ванильного визуала (~0.35–0.45 м).
- Материалы (тёмный металл + светящийся зелёный) создаются один раз и
  кэшируются; шейдер берётся с материалов ванильного клона (fallback — Standard),
  чтобы освещение совпадало с игрой.
- **Отключение:** `UseCustomModel = false` в конфиге (раздел «Пушка») и
  перезапуск игры — останется ванильный внешний вид. Если ванильная иерархия
  префаба в новой версии игры изменится, построение модели безопасно сорвётся
  (warning `[Shrinkinator]` в логе) и предмет останется с ванильным визуалом —
  мод не упадёт.

Превью модели: `shrinkinator_preview.png` (генерируется скриптом
`/tmp/render_preview.py`, matplotlib).

## Как это работает внутри (кратко)

- Предмет создаётся **без Unity Editor**: в рантайме клонируется ванильный
  префаб пистолета и его `Item`-ScriptableObject, меняются имя/цвет/цена/
  расход батареи, затем предмет регистрируется через `REPOLib.Modules.Items.RegisterItem`
  (постфикс на `StatsManager.RunStartStats` — тот же тайминг, что у самой REPOLib).
- Harmony-постфикс на `ItemGun.ShootBulletRPC` (вызывается у всех клиентов):
  рисует туман (code-created `ParticleSystem`, отдельный RPC не нужен), а на хосте —
  `Physics.OverlapSphere` в точке попадания и на середине луча, классификация целей
  (ValuableObject / EnemyRigidbody / PlayerAvatar).
- На цели заранее вешаются shrink-контроллеры (патчи на `PhysGrabObject.Awake`,
  `EnemyRigidbody.Awake`, `PlayerAvatar.Start` + `RefreshRpcMonoBehaviourCache()`);
  хост рассылает `[PunRPC]` через PhotonView цели.
- Враг: скейлится визуальный корень (Animator под EnemyParent), масса снижается
  и подкрепляется каждый кадр (игра перезаписывает её сама). Стан не вызывается.
- Игрок: скейлятся визуал `playerAvatarVisuals.meshParent` и сетевая коллизия
  `PlayerAvatarCollision.CollisionTransform`. У локального игрока дополнительно
  сжимаются шаблоны `PlayerCollision` (настоящий хитбокс), `CameraPosition` /
  crouch / crawl (высота камеры), `PlayerVisionTarget` (глаза/рука) и дальность
  захвата.

## Известные ограничения и риски

- **Версия игры.** Сборка проверена по `R.E.P.O.GameLibs.Steam` версии
  `0.4.4-ngd.0` (сигнатуры сверены с реальными DLL, в т.ч. новая сигнатура
  `ShootBulletRPC(Vector3, bool, int, PhotonMessageInfo)`). На других версиях
  игры возможны несовместимости.
- **Сборка проверена только компилятором.** В живой игре мод не тестировался
  (нет окружения с игрой): возможны логические/сетевые нюансы, которые вылезут
  только в рантайме. Смотрите `BepInEx/LogOutput.log` — все ошибки патчей
  логируются с префиксом `[Shrinkinator]`.
- **Камера и хитбоксы уменьшенного игрока** масштабируются через ванильные
  точки (`CameraPosition.playerOffset`, шаблоны stand/crouch). Если в новой
  версии игры эти поля переедут — от первого лица эффект может снова «не
  чувствоваться»; смотрите лог `[Shrinkinator]`.
- **Позиционная озвучка/AI врагов** не пересчитываются под новый размер
  (NavMeshAgent меняет только radius, скорость и зрение не трогаем).
- **Эвристика визуального корня врага.** Уменьшается первый `Animator`,
  найденный в детях `EnemyParent` (fallback — сам `EnemyParent`). Для части
  врагов это может быть «не та» ветка иерархии (например, вспомогательный
  аниматор вместо корня модели) — тогда визуально враг уменьшится частично
  или не уменьшится вовсе, хотя масса снизится корректно. Поведение по
  конкретным врагам уточняется живым тестом.
- **Ленивая загрузка PrefabRef.** Регистрация зависит от `Item.prefab.Prefab`
  ванильной пушки; если к моменту регистрации префаб не загрузился (`null`),
  предмет не зарегистрируется. Смотрите лог с префиксом `[Shrinkinator]`:
  сообщение «Ванильная пушка не найдена…» означает отложенную/сорванную
  регистрацию (мод повторит попытку при следующем `RunStartStats`).
- **Перманентное уменьшение ценностей не сохраняется между уровнями** в смысле
  сейва: ценность, доведённая до эвакуации, засчитывается по уменьшенной цене;
  если же ценность осталась на уровне и уровень пересоздаётся — предмет
  спавнится заново обычного размера.
- Повторный выстрел по уже уменьшенному врагу/игроку лишь обновляет таймер
  (scale не стакается); по ценности — уменьшает ещё раз, пока размер не упрётся
  в `ValuableMinScale`.
- Туман обрабатывается сферами OverlapSphere: цели за толстыми стенами в радиусе
  облака тоже заденет (проверки линии видимости нет).
- FALLBACK (не реализован, на случай отказа runtime-клонирования): сборка
  предмета через `.repobundle` и REPOLib-Sdk с загрузкой через
  `REPOLib.BundleLoader`.
